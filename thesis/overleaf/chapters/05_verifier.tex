\chapter{The Proposed Vericult Verifier}
\label{chap:verifier}

\section{Design Objectives}
Vericult is a standalone post-hoc evaluator. Human labels, reward-model scores, expected issues, and benchmark answers are not passed into the verifier. The system should use external evidence only where appropriate, preserve uncertainty, and leave enough trace information to inspect the final decision.

\section{Context Extraction}
The first semantic stage reads only the prompt and extracts explicitly stated context such as setting, participants, relationships, location, time, constraints, and user goal. Non-empty values require exact prompt spans. This prevents the verifier from inferring attributes such as religion or nationality from names.

\section{Cultural Applicability and Dimension Planning}
The system first checks whether culturally situated reasoning is needed. A culture-related word alone is not sufficient. If the task is applicable, the planner chooses the smallest relevant set of D01--D10 dimensions. A primary label marks relevance, not higher weight.

\section{Response Assessability}
For culturally applicable prompts, a pure refusal or empty non-answer returns \texttt{not\_assessable}. This avoids treating a refusal as a culturally correct substantive answer.

\section{Material Targets}
The response is divided into deterministic spans. Up to three decision-relevant targets are selected and classified as external fact, descriptive cultural norm, context-dependent recommendation, response-internal quality, or non-verifiable value statement. Only externally checkable categories are routed to retrieval.

\section{Neutral Verification Questions}
Each retrievable target receives two initial questions: a baseline/descriptive question and a scope/variation question. The target is visible during question generation. Candidate blindness therefore begins after the questions are generated.

\section{Retrieval and Source Handling}
LIVE uses Tavily. Queries are generated from the neutral questions and prompt context. Results are filtered for duplicates and configured exclusions before evidence synthesis. Sources are classified by provenance category, but this classification is not treated as a universal quality score.

\section{Evidence Memo and Follow-Up}
The evidence memo records the answer supported by retrieved documents, relevant scope and variation, and evidence sufficiency. Factual memo statements must be grounded in exact quotations. If evidence remains conflicting or insufficient, one gap-specific follow-up question can be searched. The process then stops.

\section{Evidence Freeze and Target Comparison}
After evidence gathering, the memo is frozen before the response target is reintroduced. Comparison can return supported, contradicted, mixed, or insufficient. Missing evidence is not contradiction.

\section{Dimension Scoring and Outcomes}
The scorer applies the rubric to the prompt, response, structured target verdicts, and frozen support quotations. Single-response outcomes include \texttt{not\_culturally\_applicable}, \texttt{not\_assessable}, \texttt{insufficient\_evidence}, \texttt{culturally\_inappropriate}, \texttt{partially\_culturally\_appropriate}, and \texttt{culturally\_appropriate}.

\section{LIVE and REPLAY}
LIVE performs search and stores evidence. An audit checks and freezes the required evidence artifacts. REPLAY uses those snapshots without live-search fallback. The thesis reports REPLAY as the primary Vericult result.

\section{Testing and Traceability}
Structured traces contain identifiers, configuration, prompt and response hashes, semantic calls, questions, evidence, memo links, verdicts, and scores. Unit and integration tests validate software contracts. Passing software tests establishes implementation conformance, not cultural accuracy.
